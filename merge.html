שליחה לרשימה

1 חיבור לחשבון Gmail

הגדרה חד-פעמית ב-Google Cloud (כ-10 דקות)
  1. נכנסים ל-console.cloud.google.com עם החשבון שממנו שולחים, ויוצרים פרויקט חדש (למשל "Startup Kid Mailer").
  2. בתפריט: APIs & Services ← Library, מחפשים Gmail API ולוחצים Enable. באותה דרך מפעילים גם Google Drive API (לכפתור "החלפה" של תמונות בעורך).
  3. APIs & Services ← OAuth consent screen: ממלאים שם אפליקציה ומייל. ב-User type בוחרים Internal (בחשבון Google Workspace של הארגון). בחשבון Gmail פרטי: External, ובשלב Test users מוסיפים את המייל שלכם.
  4. APIs & Services ← Credentials ← Create credentials ← OAuth client ID. סוג: Web application.
  5. תחת Authorized redirect URIs לוחצים Add URI ומדביקים בדיוק את הכתובת הזאת:
  6. לוחצים Create, מעתיקים את ה-Client ID ומדביקים אותו בשדה למעלה.

הכתובת בשלב 5 זהה בכל מחשב ובכל תיקייה (למזהה התוסף יש מפתח קבוע ב-manifest.json), ולכן מגדירים אותה פעם אחת בלבד.

2 תבנית ונושא

אפשר להשתמש במשתנים גם בנושא, למשל: הצעה לשיתוף פעולה עם {{שם הארגון}}

הנמענים מתחלקים לסירוגין: אחד מקבל A, הבא B. כדי ליצור גרסה B: פותחים את העורך ב-Gmail, משנים מה שרוצים לבדוק, ולוחצים "שמירה כתבנית". אחרי השליחה, "ייצוא תוצאות" מראה מי קיבל איזו גרסה, כדי להשוות למי שענה.

4 שליחה

הבדיקה נשלחת עם הנתונים של השורה שמוצגת בתצוגה המקדימה.

מונע שליחה כפולה: מי שכבר קיבל מייל בקמפיין עם השם הזה לא יקבל אותו שוב, גם אם טוענים את הקובץ מחדש.

שניות

מגבלת Gmail: עד 2,000 מיילים ביום בחשבון Workspace (500 בחשבון פרטי). החשבון עלול להיחסם זמנית אם עוברים אותה.

נמענים

#מיילשםנשלח בעברסטטוס

גיבוי והעברה למחשב אחר

קובץ אחד עם כל ההגדרות: Client ID, הערכים שמילאתם בשדות (כולל קישורי התמונות מ-Drive), התבניות שלכם, רשימת ההסרה, היסטוריית השליחה, וגם ההעדפות.

בייבוא הנתונים מתמזגים עם מה שכבר יש במחשב הזה, ושום דבר לא נמחק. היסטוריית השליחה ורשימת ההסרה מתאחדות, כדי שאף אחד לא יקבל את אותו מייל פעמיים. הקובץ כולל כתובות מייל של נמענים, אז לא לשתף אותו עם אנשים מחוץ לצוות.

במחשב החדש צריך להוסיף ב-Google Cloud, באותו Client ID, גם את כתובת ההפניה שלו. היא מופיעה בשלב 1, כי היא שונה בכל מחשב.
